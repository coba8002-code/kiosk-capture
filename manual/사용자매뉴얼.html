처음에는 이것만 기억하세요

  1. 배포 ZIP을 새 폴더에 모두 풀고 KFA.exe를 실행합니다.
  2. 휴대전화에서 촬영 앱을 열고, 먼저 2~3장으로 전달 과정을 시험합니다.
  3. 촬영 ZIP을 PC로 옮겨 진단하고, 필요한 실측·검토 결과를 저장합니다.

키오스크 자체에는 프로그램을 설치하지 않습니다. 휴대전화는 브라우저로 촬영하고, Windows PC가 분석과 보고서 생성을 담당합니다.

이 도구와 보고서는 법정 적합성 인증이 아닙니다. 실제 사용자 시험과 필요한 전문 실측을 대체하지 않습니다.

02 · 휴대전화 연결

촬영 앱 열기

안드로이드는 Chrome, 아이폰은 Safari에서 아래 주소를 열어 시험할 수 있습니다. 앱스토어 설치 파일은 없습니다.

https://coba8002-code.github.io/kiosk-capture/

두 가지 연결 방식

웹 주소로 접속: PC와 같은 와이파이일 필요가 없습니다. 처음 접속에는 인터넷이 필요합니다. 현재 GitHub 사이트에는 최근 로컬 캐시 수정이 아직 반영되지 않았습니다.

PC의 ‘촬영 앱 켜기’: 최신 배포본 안의 앱을 PC가 제공합니다. 휴대전화와 PC를 같은 와이파이에 연결하고 표시되는 QR을 스캔합니다. 로컬 HTTP 접속은 오프라인 재실행이 지원되지 않을 수 있습니다.

  1. 기기 등록에서 기기 ID·위치·제품 구분 등 실제 정보를 입력합니다.
  2. 조건부 기능과 면제는 해당 근거를 확인한 경우에만 선택합니다.
  3. 촬영 시작을 누르고 안내되는 사진·영상 목록을 따릅니다.

처음에는 전체 촬영 전에 2~3장을 저장하고 ZIP을 PC에서 열어 보세요. 카메라·사진 접근을 요청하면 필요한 권한을 허용합니다.

브라우저 내부 저장소는 영구 보관함이 아닙니다. 사이트 데이터 삭제, 저장 공간 부족, 브라우저 정리로 자료가 없어질 수 있으므로 ZIP 백업을 확보하세요.

사진 계측의 조건

  • 인쇄 마커의 실제 크기가 맞아야 합니다. ‘용지에 맞춤’으로 축소하지 않습니다.
  • 마커와 대상이 서로 다른 깊이에 있으면 사진 치수는 신뢰하기 어렵습니다.
  • 사진의 버튼 윤곽이 실제 누름 영역과 같은지 사람이 확인해야 합니다.
  • 경계값에 가까운 치수는 자·캘리퍼 등으로 다시 측정합니다.

개인정보 가리기

사진의 얼굴·카드번호 등 불필요한 개인정보는 앱의 가리기 기능으로 확인하고 처리하세요. 영상·음성이 같은 방식으로 자동 마스킹된다고 가정하면 안 됩니다. 불필요한 개인정보가 없는 시험 자료를 사용하세요.

사진 대비는 원본 화면 색상과 같지 않을 수 있습니다. 조명·반사·노출이 결과에 영향을 줍니다.

04 · ZIP 전달

PC에서 진단하기

  1. 촬영 앱에서 제출 전 확인 화면으로 이동합니다.
  2. ZIP 만들기를 실행하고 파일 준비가 끝날 때까지 기다립니다.
  3. 내려받기 또는 공유 · 파일 앱에 저장을 누릅니다.
  4. 파일 앱에서 실제 ZIP이 있는지 확인한 뒤 PC로 옮깁니다. 민감 자료 전송은 소속 기관의 승인된 방법을 사용합니다.
  5. PC의 다운로드 폴더 등에 ZIP을 놓고 KFA 조작판에서 사진 고르기를 누릅니다.
  6. 목록에서 해당 촬영을 선택해 진단합니다. ZIP은 프로그램이 새 폴더에 풀어 처리합니다.

아이폰에서 내려받기가 안 되면

파일 준비 화면의 공유 · 파일 앱에 저장을 먼저 시도합니다. 공유 기능이 표시되지 않으면 내려받기 링크를 다시 누르거나 길게 눌러 저장 방법을 확인하세요. 저장 취소는 성공이 아닙니다.

PC로 옮긴 ZIP을 실제로 읽을 때까지 원래 촬영 자료를 삭제하지 마세요.

같은 자료를 다시 검토할 때

ZIP을 다시 선택하면 새 제출본으로 가져옵니다. 기존 검토를 이어가려면 목록에서 가져온 폴더를 선택하세요. 기본 위치는 실행 폴더 아래 assets\bundles\capture-…입니다.

ZIP이 목록에 없다면 다운로드 폴더로 옮긴 후 다시 찾으세요. 일반 사진 ZIP이 아니라 촬영 앱이 만든 manifest.json 포함 번들이 필요합니다.

숫자·오차·검사 범위 입력

처음 화면에서 검토 · 실측 입력을 누르고 촬영을 선택합니다. 분석이 끝나면 검토자 이름을 입력합니다.

자동 수치 비교입력할 값
1.c 버튼 크기전체 대상의 최소 너비·높이 (mm)
1.d 조작력전체 조작부의 최대 힘 (N)
3.g 문자 높이필수 문자의 최소 높이 (mm)
9.a 조작부 높이바닥 기준 최저·최고 높이 (mm)
9.b 정보 높이필수 시각 정보의 최상단 최대 높이 (mm)
  1. 항목의 입력 방식을 새 실측값으로 비교로 바꿉니다.
  2. 숫자와 오차 한계를 입력합니다. 모르는 오차를 0으로 채우지 말고 비워 두세요.
  3. 측정 조건, 장비·교정·오차 근거, 검사 범위와 빠진 부분을 적습니다.
  4. 기준과 비교하기를 눌러 계산 결과를 확인합니다.
  5. 모든 대상·상태를 확인한 경우에만 전수 확인을 체크합니다. 측정 담당자가 근거와 결과를 확인한 뒤 담당자 확인을 체크합니다.

오차 한계는 측정자가 근거를 가지고 입력하는 범위입니다. AI 확신도나 교정 성적서의 불확실성과 동일하지 않습니다. 오차 미입력·불완전한 검사 범위·담당자 확인 누락은 미판정 사유가 됩니다.

1.i 배출물과 5.c 음량은 복합 조건이 있어 기존 담당자 판정 입력을 유지합니다. 수치 비교는 입력값이 정확하고 전체 대상이 대표되었다는 사실까지 증명하지 않습니다.

위반 의심 검토

근거 사진 링크와 측정 내용을 확인합니다. 승인은 부적합 확정, 반려는 미판정입니다. 반려했다고 적합이 되지 않습니다. 판단이 어려우면 변경하지 않고 남깁니다.

저장 순서

  2. 저장한 결과로 보고서 다시 만들기를 누릅니다.
  3. 완료 후 처음 화면의 결과 폴더 열기에서 새 report_… 폴더를 확인합니다.
  4. 리포트 A는 점주용, 리포트 B는 담당자용입니다. HTML을 열고 Ctrl+P → PDF로 저장하면 됩니다.

07 · 선택 설정

OCR과 외부 AI 사용

기본 사용에는 Python·API 키가 필요 없습니다

EXE로 사진 선별, 수치 실측 비교, 검토·보고서를 사용할 수 있습니다. 다만 EXE에는 OCR 모델이 포함되지 않아 사진의 문자 높이 자동 추정은 별도 Python 실행이 필요합니다.

한글 OCR이 필요할 때

Python과 pip를 사용할 수 있는 PC에서 배포본의 소스 폴더를 터미널로 열어 실행합니다. 모델 첫 다운로드에는 인터넷이 필요하며, 아래 명령은 EXE가 아닌 소스 실행용입니다.

python -m pip install -r requirements.txt
python -m pip install rapidocr
python kfa.py calibrate-ocr
python kfa.py

교정 결과를 확인하고 같은 소스 조작판에서 진단하세요. 현장 측정으로 정확도를 확인하기 전에는 OCR 결과를 확정값으로 취급하지 않습니다.

외부 AI는 선택 기능입니다

현재 공급자는 이미지 중심이며, API 키를 넣는 것만으로 음성·영상 분석이 해결되지는 않습니다. 계정에서 사용 가능한 모델 ID와 공급자 설정을 확인해야 합니다.

python -m pip install anthropic
# PowerShell에서 실제 값으로 설정
$env:ANTHROPIC_API_KEY = "본인의 키"
$env:KFA_L2_MODEL = "계정에서 사용 가능한 모델 ID"
python kfa.py ingest "촬영폴더" --l2 anthropic

이 명령은 사진을 외부 API로 전송할 수 있습니다. 개인정보와 전송 권한을 확인한 후 진행하세요. 키를 매뉴얼·촬영 ZIP·공유 저장소에 넣지 마세요. 실제 API 호출과 모델 품질은 별도 검증이 필요합니다.

자주 막히는 지점

증상확인할 것
실행 후 화면이 안 보임잠시 후 콘솔에 표시되는 로컬 주소로 접속. ZIP 내부 실행 여부 확인.
폰에서 PC QR 접속 실패같은 와이파이인지 확인. 게스트망 격리·방화벽 정책을 담당자에게 확인.
오프라인에서 앱이 안 열림첫 접속·캐시 준비 여부 확인. 로컬 HTTP는 오프라인 재실행을 기대하지 않기.
마커를 못 찾음인쇄 크기·반사·흐림·잘림을 확인하고 대상과 같은 평면에서 재촬영.
미판정이 많음오류만을 뜻하지 않음. 필요한 사진·실측·검사 범위·담당자 확인을 점검.
다른 창에서 변경했다고 표시기존 파일을 보호하는 동작. 검토 화면을 다시 열고 최신 기록을 확인.
보고서 생성 실패저장한 review.json은 남음. 같은 가져온 폴더로 다시 진단.
측정 숫자는 넣었는데 저장 안 됨입력 방식이 ‘새 실측값으로 비교’인지, 이름·조건·장비·검사 범위가 채워졌는지 확인.

백업할 것

원본 촬영 ZIP, 가져온 폴더의 manifest.json·사진·review.json, 생성된 report_… 폴더를 함께 보관합니다. review.json에는 검토 변경 이력이 포함됩니다.

인증서 개인키·API 키는 배포 자료에 섞지 않습니다. 기존 설치를 삭제하거나 assets를 비우기 전에 자료를 복사해 확인하세요.

처음부터 모든 항목을 촬영하기보다 아래 과정을 작은 자료로 한 번 완료하세요.

  1. Windows에서 KFA.exe를 실행해 조작판을 열었다.
  2. 마커를 100%로 인쇄하고 20mm 눈금을 확인했다.
  3. 휴대전화에서 기기 ID를 입력하고 2~3장을 촬영했다.
  4. 가려야 할 개인정보를 확인했다.
  5. ZIP을 저장하고 파일 앱에서 존재를 확인했다.
  6. PC로 옮긴 ZIP을 프로그램이 읽었다.
  7. 검토 화면에서 근거를 보고 실측값 하나를 비교했다.
  8. 검토 저장 후 새 보고서를 만들고 내용을 확인했다.
  9. 원본 ZIP·review.json·보고서를 백업했다.
