# 키오스크 현장 접근성 진단 — kiosk-field-audit

현장에 이미 설치된 무인정보단말기를 촬영·계측해
**고시 [별표 5] 무인정보단말기 접근성 검증 기준 40항목**으로 판정하는 시스템.

이 시스템의 요지는 AI 성능이 아니라 **경계**다.
무엇을 판정했고, 무엇을 판정하지 못했고, 못한 것은 누가 이어받는지를
항목 단위로 적어내는 것 — 그게 성적표와 작업지시서의 차이다.

## 세 개의 트랙

별표5 40항목은 “누가 판정할 수 있는가”로 갈린다.

| 트랙 | 항목 | 판정 주체 | 왜 |
|---|---:|---|---|
| **A · AI 자동** | 29 | AI 1차 → 검토자 확정 | 촬영물에서 계측하거나 해석할 수 있다 |
| **B · 점주 셀프** | 4 | 점주 현장 확인 | 카메라가 볼 수 없는 동작 (이어폰 연결 시 스피커 차단 등) |
| **C · 전문 실측** | 7 | 계측 장비 | 조작력 22.2N · 음량 65dBA · 활동공간 · 조도 |
| **D · 사용자 검증** | — | 장애인·고령자 12명 | **이 시스템으로 대체 불가. 범위 밖.** |

그리고 A 트랙 안에서도 AI가 말할 수 있는 범위가 다르다.

```
양방향(both)      23항목  ██████████████··········  57%   적합·부적합 모두 제시
위반만(fail_only) 13항목  ████████················  33%   위반은 잡지만 적합은 증명 못 함
관여 안 함(none)   4항목  ██······················  10%   맥락 자료만
```

> **AI가 ‘적합’까지 말할 수 있는 항목은 40개 중 23개(57%)뿐이다.**
> 이 숫자를 숨기지 않고 리포트에 인쇄하는 것이 이 제품의 정직성이다.

## 절대 우회하지 말 것 — `engine/verdict.py`

```python
from engine import rules as R
from engine.verdict import Evidence, Verdict, apply_ai_scope

rs = R.load()

# 1.b 는 ai_verdict_scope: fail_only — AI가 '적합'을 증명하지 못하는 항목
a = apply_ai_scope(
    rs["1.b"], Verdict.PASS,
    evidence=Evidence(criterion_id="1.b", measured={"최소 간격": 2.8}, confidence=0.95),
)

a.verdict          # Verdict.UNDETERMINED   ← PASS 가 강등됐다
a.downgraded_from  # Verdict.PASS
a.reason           # Undetermined.NEEDS_MEASURE
a.next_owner       # '전문 실측'
```

불변 규칙 여섯 가지:

1. **AI는 ‘부적합’을 확정하지 않는다.** AI의 FAIL 은 `위반 의심`까지이고,
   검토자 승인을 거쳐야 `부적합`이 된다.
2. **`fail_only` 항목의 AI PASS 는 무조건 `미판정`으로 강등된다.**
   사유는 `track` 이 아니라 **`final_by`** 가 정한다.
3. **근거 4종이 없는 판정은 버려진다** — 근거 이미지 · 측정값 · 항목 ID · 확신도.
4. **확신도 0.85 미만은 검토자 큐로 간다.**
5. **검토자가 반려해도 ‘적합’이 되지 않는다.** 미판정으로 되돌아갈 뿐이다.
6. 실측·점주 판정(`record_external`)만 사정거리 제한을 받지 않는다.

모든 AI 판정은 `apply_ai_scope()` 를 통과해야 한다.
`Assessment` 를 직접 만드는 코드 경로가 생기면 위 규칙이 전부 무력화된다.

## 기준 스케일 마커 BFK-MARK-A

사진에서 밀리미터를 읽지 못하면 문자 높이 7.25mm, 버튼 한 변 12mm,
버튼 간격 2.5mm, 배출물 돌출 20mm, 작동부 높이 400~1,220mm 가
전부 ‘추정’으로 떨어진다. 신용카드 크기 인쇄물 한 장이 이걸 바꾼다.

```bash
python tools/make_marker.py --sheet
```

```
BFK-MARK-A   카드 85.6×54.0mm   마커 40.0mm
             762dpi = 30 px/mm (정수 격자)

  [OK  ] assets/BFK-MARK-A_id0.png
          2568×1620px   검출 변 39.9667mm   보정 후 40.0mm   왜곡 1.0
```

**인쇄 규칙 — 어기면 환산이 통째로 틀어진다**

- **‘실제 크기 100%’로 인쇄한다.** ‘용지에 맞춤’은 절대 쓰지 않는다.
- 무광 코팅 200g 이상. 유광은 화면 반사와 겹쳐 검출률이 떨어진다.
- 인쇄 후 카드의 20mm 눈금자를 실제 자로 대어 검증한다.
- 마커는 **측정할 평면과 같은 면**에 붙인다. 화면과 물리 버튼은 깊이가 다르므로 각각 따로.

왜 762dpi 인가 — 762dpi 는 정확히 30 px/mm 다. 이 격자에서만 카드(2568×1620px)와
마커(1200px = 6셀 × 200px)가 모두 정수로 떨어진다. 600dpi 로 만들면 렌더 격자가
어긋나 검출 변이 40mm 가 아니라 **39.50mm**(−1.3%)로 나오고, 그 오차가 문자 높이
판정을 0.09mm 씩 밀어버린다.

## L1 계측 — 코드가 계산하는 층

같은 입력이면 같은 값이 나온다. 법적 방어력은 여기서 나온다.

```python
from engine.calc import contrast

r = contrast.evaluate("#9AA3AB", "#FFFFFF", required=4.5, dispersion=6.0)
r.ratio      # 2.56
r.passed     # False
contrast.nearest_passing_color("#9AA3AB", "#FFFFFF")   # '#6B747C' → 4.52:1
```

| 모듈 | 항목 | 주의 |
|---|---|---|
| `contrast.py` | 3.i(4.5:1) · 3.j(7:1) | 사진 색 산포가 크면 확신도를 깎는다. 무보정 원본(S1-04) 사용 |
| `scale.py` | 마커 환산 | 호모그래피는 **한 평면에만** 성립. 왜곡비 2.5 초과·프레임 대비 3% 미만은 거부 |
| `geometry.py` | 1.b · 1.c · 1.i · 9.a · 9.b | 1.c 는 경계상자(별표5 144mm²)와 누름 면적(KS 150mm²)을 **따로** 계산. 물리 간격 0.5mm 는 촬영 오차와 겹침 → `can_confirm_pass` 확인 |
| `text_height.py` | 3.g | `CAP_RATIO` 실측 교정 완료. `OCR_BOX_FACTOR` 미교정 → 확신도 0.85 상한 |
| `flash_rate.py` | 8.a | 깜박임 1회 = 반대 방향 변화 **한 쌍**. 별표5는 “3회 **미만**” |
| `sound.py` | 5.c | 측정점은 **표준이 아니라 본 SOP** 가 정의. 조건을 리포트에 병기 |

> 명도 대비 상수는 형제 프로젝트(`../BUILD_SPEC_베리어프리_접근성_플랫폼.md`)의
> TypeScript `packages/core` 와 **동일해야 한다.** 갈라지면 디자인 단계와 현장 진단이
> 같은 화면에 다른 값을 낸다.

## 리포트 두 벌

같은 판정 데이터에서 독자별로 두 벌을 만든다.

**A · 점주용 한 장** — 실행 카드 3단(오늘 / 이번 분기 / 교체 시 검토).
각 카드에 담당·난이도·비용 대역. 점수는 맨 아래에 둔다. 위로 올리면 행동이 사라진다.

**B · 발주·지자체용** — 별표5 40항목 매트릭스 + **미판정 항목과 다음 담당**.
미판정을 빈칸이 아니라 명시 항목으로 인쇄하는 것이 이 리포트의 신뢰 장치다.

```
  항목    사유          다음 담당       조치
  1.d   전문 실측 필요    전문 실측      푸시풀 게이지 (0.1N 분해능)로 22.2N 이하 확인
  1.f   점주 확인 필요    점주          카드를 반대로 넣었을 때 시각·청각 안내와 배출이 되는지
  2.b   입력 부족       현장 재촬영     S2-02 타임아웃 대기 구간 누락 — 20초 경고 확인 불가
  1.a   AI 판정 범위 밖  검토자         위반 신호 0건 — 적합은 AI가 확정하지 못함
```

## 하면 안 되는 것

- ❌ **“접근성 100% 보장”, “자동으로 인증 통과”** 같은 단정 표현.
  UI·마케팅·API 응답 어디에도 쓰지 않는다.
- ❌ **KS X 9211:2025 본문을 리포트에 싣는 것.** 원문에 “상업적 활용을 금지합니다”
  표시가 있다. `ks_ref` 에는 절 번호만 적고 설명은 자체 문장으로 쓴다.
  (별표5는 행정규칙 = 공공저작물이므로 원문 인용 가능)
- ❌ **`apply_ai_scope()` 우회.** 이 함수가 이 제품과 ‘그럴듯한 점수표’를 가르는 유일한 선이다.
- ❌ **마커 없이 픽셀을 mm 로 환산하는 것.**
- ❌ **측정 조건 없이 dBA 값을 인쇄하는 것.** 표준이 측정 거리를 규정하지 않아
  우리 SOP 가 정의한 조건이다. 조건이 빠지면 값이 재현되지 않는다.
- ❌ **HWP/HWPX 를 무에서 생성하는 것.** 한글이 열어 주는지는 실제 한글에서만
  검증된다. 발주처 서식을 받아 채운다 (`engine/report/export.py`).

## 표준이 비워 둔 자리

이 사업이 다루는 세 표준은 생각보다 많은 것을 열어 두었다. 그 자리를 우리가 채웠고,
채웠다는 사실을 리포트에 표시한다.

| 무엇 | 표준의 상태 | 우리 결정 |
|---|---|---|
| 1.c 면적 | 별표5(경계상자 144mm²)와 KS §5.6.2(누름면 150mm²)가 **다른 것을 잰다** | 두 값을 따로 계산, 법적 판정과 권고를 분리 인쇄 |
| 5.c 측정 거리 | 별표5·KS·EN 301 549 §5.1.3.12 **모두 규정 없음** | 전면 300mm · 귀 높이 1,500/1,150mm · 낮은 값 채택 |
| 3.g 문자 높이 정의 | KS 비고 3의 란돌트 고리 근거만 | 잉크 실제 높이로 정의, 폰트 메트릭 실측 교정 |
| 제출 형식 | 규정 없음 | 웹+PDF 기본, 발주처 HWP 서식은 채우기 방식 |
