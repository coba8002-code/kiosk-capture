# 서비스 검토 및 개선 기록 — 2026-09-09

## 2026-09-23 촬영 서버 실행 오류 수정

`tools/serve_app.py`의 `_tail()` 안내 문자열에 실제 줄바꿈이 끼어 문법 오류가 발생했다. PyInstaller가 `invalid module named tools.serve_app` 경고만 남기고 실행파일을 생성하여, 촬영 앱 실행 시 ImportError가 발생했다. 문자열을 수정하고 빌드 전에 engine/tools의 모든 Python 파일을 컴파일 검사하도록 추가했다. 재발 검사는 `tests/test_capture_server.py`, 실제 배포 EXE의 HTTP 확인은 `python tools/smoke_capture_exe.py <KFA.exe>`로 수행한다.

## 종합 평가

현재 제품은 현장 진단을 보조하는 파일럿 도구다. 촬영 → ZIP → PC 분석 → 보고서 경로와 사람의 검토를 남기는 구조는 유효하다. 다만 코드 연결 개수만으로 상용 준비도를 판단할 수 없다. 실제 기기 촬영의 정확도, 실제 고령자·장애인 사용성, 휴대전화별 저장 성공률은 별도 검증이 필요하다. 과거 가상 패널 의견은 실제 참여자 실험 결과가 아니다.

| 영역 | 검토 결과 | 필요한 개선 |
|---|---|---|
| 진단 원칙 | AI 위반 의심과 검토자 확정이 분리됨 | 이 경계를 유지하고 항목별 실제 현장 정확도 측정 |
| 자료 관리 | 같은 이름 재수입 시 과거 파일·검토 기록 혼입 가능 | 매번 독립된 가져오기 폴더와 보고서 폴더 사용 |
| 입력 안전성 | 번들 외부 파일 참조, ZIP 경로 검사, 화면 문자열 삽입 취약 | 경로·형식 검증, 안전한 텍스트 표시 |
| AI 근거 | 잘못된 확신도와 전송하지 않은 자료 인용 수용 가능 | 유한한 확신도 및 실제 전송 파일 인용만 허용 |
| 휴대전화 | 프로토콜 초기 캐시 누락, 다른 앱 캐시 삭제 가능 | 프로토콜 사전 저장 및 자체 캐시만 정리 |
| 기능 안내 | S5를 API 설정만으로 분석 가능한 것으로 표시 | 현 공급자의 음성·영상 미지원 명시 |
| 설치 | 브라우저 조작판은 있으나 OCR 실행 방식이 다름 | 통합 OCR 배포는 모델 포함 빌드·용량·설치 검증 후 추진 |
| 보고서 | 확대 기능을 근거로 문자 높이 개선을 미루는 문구 | 각 항목을 독립적으로 확인하도록 변경 |

## 이번 수정

- ZIP 가져오기마다 새 폴더를 사용해 이전 review.json과 촬영물이 섞이지 않도록 했다. 기존 자료는 보존한다.
- ZIP 경로 이동, 절대 경로, 스트림 경로, 중복 이름, 심볼릭 링크와 과도한 해제 용량을 차단한다.
- manifest의 촬영 파일은 번들 내부 일반 파일로 제한한다. 파일 찾기에서 비정상 manifest를 걸러낸다.
- PC 목록의 촬영 대상 이름과 경로를 HTML로 해석하지 않고 텍스트로 표시한다.
- 보고서는 진단 실행마다 새 폴더에 저장한다. 동일 기기 재진단도 과거 보고서를 덮어쓰지 않는다.
- AI 확신도 NaN/무한대/범위 초과를 거절한다. 인용은 실제 전송한 파일에 한정한다.
- 지원하지 않는 영상 파일이 앞에 있어도 뒤의 지원 이미지까지 확인한 뒤 이미지 수 제한을 적용한다.
- 오프라인 필수 파일에 protocol.json을 추가하고 캐시 저장 완료를 기다린다. 자체 이름의 캐시만 삭제한다.
- gaps의 S5 표시를 음성·영상 자동 분석 미지원으로 바꾼다. 코드 연결 0개 누락과 제품 완성을 구분한다.
- 문자 확대가 있어도 기본 문자 높이 개선을 별도로 확인하도록 보고서 문구를 바꾼다.
- 실행파일에 누락된 사용성 참고 규칙을 포함한다.

## 아직 해결되지 않은 제품 과제

검증 결과: Python 전체 회귀 테스트 244개 통과. 마지막 AI 요청 자료 목록 수정 후 관련 회귀 테스트 20개 재통과. Node 실행으로 서비스 워커의 프로토콜 사전 캐시, 다른 앱 캐시 보존, 서버 오류 시 캐시 복귀, 앱 범위 밖 요청 무시를 확인했다. 실제 휴대전화와 외부 API 호출 시험은 수행하지 않았다.

1. 실제 안드로이드·아이폰 각각에서 촬영, 개인정보 확인, ZIP 저장, PC 가져오기, 재진단을 끝까지 시험한다. 저장 성공은 PC에서 파일을 열어 확인한다.
2. 실제 키오스크에서 기준 미달·충족·경계 사례를 수집하고 줄자 및 원본 화면값과 비교한다. 항목별 누락률·오탐률·측정오차·미판정 비율을 기록한다.
3. 음성·영상 분석은 현재 Anthropic 이미지 공급자가 처리하지 않는다. 실제 지원 공급자 선정과 개인정보 처리 정책, 검증용 자료가 필요하다. API 키 입력만으로 해결되지 않는다.
4. OCR 모델은 현 EXE에 없다. Python 소스 실행 방식으로 사용 가능하지만 별도 통합 설치본 개선이 필요하다.
5. 검토자 실측 입력과 승인도 브라우저에서 처리하도록 개선할 여지가 있다. 현재 CLI 기능은 존재하지만 일반 사용자 편의성이 부족하다.
6. API 모델 ID·실제 호출·응답 품질은 사용자의 설정으로 별도 검증해야 한다. 이번 검토에서는 현장 촬영물을 외부 전송하지 않았다.

## 현장 시험 합격 조건 제안

- 첫 사용자 한 명이 도움 없이 촬영 3건을 PC로 옮겨 보고서까지 열 수 있을 것.
- 같은 이름의 ZIP을 두 번 가져와도 이전 검토 내용과 파일이 혼입되지 않을 것.
- 오프라인 재실행 시 촬영 목록이 열리고, 온라인 복귀 후에도 기존 자료가 남을 것.
- AI가 확정 부적합을 만들지 않고, 미지원 자료·읽기 실패가 미판정으로 드러날 것.
- 기준 경계 사례는 실측과 비교해 검토 대상으로 남는지 확인할 것.

시험 결과는 기기 모델, OS·브라우저 버전, 날짜, 파일 ID, 소요 시간과 실패 단계를 함께 기록한다. 기능 점수나 완료율은 이 결과가 축적되기 전에는 제시하지 않는다.

## 수정본 사용

### 0.3.0 — 측정값 기반 비교

검증: 전체 Python 테스트 274개 통과. 검토 화면 JavaScript 문법 검사 통과. 7.25mm ±0.1mm 문자 높이 입력이 미판정/재측정으로 처리되는 것을 확인했다. 실제 키오스크 측정 오차와 실제 사용자의 화면 조작 검증은 별도 과제다.

검토 화면에서 1.c 버튼 크기, 1.d 조작력, 3.g 문자 높이, 9.a 조작부 높이, 9.b 정보 높이는 숫자로 입력한다. 입력 방식에서 **새 실측값으로 비교**를 선택하고 수치·단위·오차 한계·장비/교정 근거·측정 조건·검사 범위를 기록한다. **기준과 비교하기**로 결과를 먼저 확인한 뒤 담당자 확인을 체크하고 저장한다. 기존 기록 유지는 입력을 바꾸지 않는다.

오차 한계는 측정자가 근거를 갖고 입력하는 범위이며, 기기 분해능만으로 자동 결정하거나 통계적 불확실성이라고 부르지 않는다. 모르면 빈칸으로 남기며 미판정으로 처리한다. 기준을 걸치는 구간은 재측정 대상으로 남긴다. 미달은 한 대상에서도 확인될 수 있지만 적합에는 모든 대상·상태 확인이 필요하다. 담당자 확인 없이 확정하지 않는다.

5.c 음량과 1.i 배출물은 복합 조건 확인이 필요하므로 기존 담당자 판정 입력을 유지한다. 1.c 누름 면적 설계 권고는 법정 경계상자 비교에 섞지 않는다. 수치 입력을 추가하면서 기존 실측이 사진 추정을 명시적으로 대체하도록 수정했다.

보고서 A/B에 수집 세트별 파일 수, 실제로 자동 확인하지 못한 항목, 사진 분석 범위와 측정 오차 설명이 붙는다. 원본 화면 직접 분석, 영역별 깜박임 분석, 실제 사용자 시나리오 시험과 측정 성능 검증은 아직 구현·검증이 더 필요하다. 이번 개선을 현장 정확도 검증 완료로 해석해서는 안 된다.

### 0.2.2 추가 개선

처음 화면의 **검토 · 실측 입력** 버튼 → 촬영 선택 → 근거 사진 확인 → 검토자 이름 입력 → 필요한 항목만 변경 → 검토 결과 저장 → 보고서 다시 만들기 순서로 사용한다. 실측값에는 단위와 조건을 함께 적는다. 해당 없음은 사유를 적는다. 승인하면 부적합, 반려하면 미판정으로 남는다.

저장 시 기존 면제·등급·다른 항목 입력을 보존하며, 변경 이력과 항목별 승인 담당자를 기록한다. 다른 창에서 파일이 바뀌면 저장을 거절하고 재조회하도록 안내한다. 저장 후 보고서 생성에 실패해도 검토 기록은 남는다. ZIP을 다시 선택하면 새 제출본으로 가져오므로, 기존 검토를 이어갈 때에는 목록의 가져온 **폴더**를 선택한다.

브라우저 검토 화면은 승인·반려와 실측 7항목을 지원한다. 면제·등급 입력의 화면화와 OCR 통합 설치, 음성·영상 분석, GitHub 사이트 갱신은 아직 남아 있다. 이번 브라우저 자동 조작 도구는 환경 오류로 연결되지 않아 화면의 실제 클릭·레이아웃 시험은 완료하지 못했다. HTTP 조회와 JavaScript 문법, 저장/충돌/판정 경계 자동 테스트로 확인했다.

KFA-0.2.1.zip을 새 폴더에 풀고 KFA.exe를 실행한다. 0.2.0 폴더의 결과와 검토 기록은 그대로 보존한다. 기존 설치·사용 PDF는 기본 사용법 참고용이며, 이번 변경과 제한 사항은 이 문서를 함께 읽는다.

휴대전화 앱 수정은 로컬 app/과 assets/web/에 반영했다. 기존 GitHub Pages 사이트에는 이번 작업에서 업로드하지 않았다. 웹용 수정본은 assets/web/의 정적 파일을 기존 호스팅 저장소에 반영해야 적용된다.
