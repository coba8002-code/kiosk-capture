# 운영 가이드 — 무엇을 설치하고, 무엇을 해야 하나

이 문서는 **지금 당장 할 수 있는 것**과 **아직 개발이 남은 것**을 나눠서 알려준다.
결론부터: **KFA.exe 하나면 설치 끝이고, 오늘 현장에 나갈 수 있다.
폰으로 찍어 PC 에서 리포트까지 나온다.**

---

## 0. 지금 어디까지 와 있나

| | 상태 | 무엇 |
|---|---|---|
| 룰 DB · 촬영 프로토콜 · 실측 SOP | **완성** | 별표5 40항목, 촬영 24컷, 실측 7항목 |
| L1 결정론적 계측 (6모듈) | **완성** | 명도대비 · 마커환산 · 치수 · 문자높이 · 깜박임 · 음량 |
| 판정 모델 (AI 사정거리 강제) | **완성** | 211개 테스트 통과 |
| 리포트 생성 (A/B · CSV · JSON) | **완성** | 점주용은 쉬운 말 · 사용성 주의 포함 |
| 마커 카드 · 현장 체크리스트 | **완성** | 인쇄해서 바로 사용 |
| 화면 설계 (9종) | **완성** | Figma. 코드로는 미구현 |
| **수집 앱 (PWA)** | **완성** | 폰에서 촬영 → ZIP. https 로 켜면 오프라인 → §2-3 |
| **사진 → 판정 파이프라인** | **완성** | `KFA.exe ingest` — 3.i·3.j·1.b·1.c·8.a 자동 판정 (+3.g, OCR 시) |
| **작동부 윤곽 검출** | **완성** | 마커 평면에서 버튼을 찾아 1.b·1.c 계측 |
| **L2 멀티모달 판정** | **완성 · SDK 설치됨** | 25항목. `ANTHROPIC_API_KEY` 만 넣으면 된다 → §5 |
| **OCR 연동 (3.g)** | **완성 · 동작 중** | RapidOCR 한글(PP-OCRv5) · 교정 완료 → §5 |
| **검토자 콘솔 · API · DB** | 없음 | 실증 2곳 규모면 없어도 된다 |

> **앱 → ZIP → 엔진 → 리포트** 왕복이 성립한다.
> `KFA.exe gaps` 를 실행하면 지금 무엇이 비어 있는지 코드에서 직접 대조해 보여주고,
> `KFA.exe self-check` 는 **우리 화면이 우리 기준(4.5:1)을 지키는지** 검사한다.

## 1. 설치

### 1-0. 가장 쉬운 길 — 실행 파일

`KFA.exe` 를 더블클릭한다. **파이썬을 설치하지 않아도 된다.**
USB 로 복사해도 그대로 돌고, 결과물은 exe 옆 `assets` 폴더에 쌓인다.

아래 1-1~1-3 은 **소스로 개발할 때만** 필요하다.

### 1-1. 파이썬 설치 (개발용)

**Windows**

[python.org/downloads](https://www.python.org/downloads/) 에서 3.10 이상을 받아 설치한다.
설치 화면 첫 페이지의 **`Add python.exe to PATH`** 를 반드시 체크한다.

**macOS**

```bash
brew install python@3.12
```

확인:

```bash
python --version
```

`3.10` 이상이 나오면 된다. (Windows 에서 `python` 이 안 먹으면 `py --version`)

### 1-2. 패키지 설치

프로젝트 폴더에서:

```bash
pip install -r requirements.txt
```

설치되는 것은 5개뿐이다. 무거운 것 없다.

| 패키지 | 왜 필요한가 |
|---|---|
| PyYAML | 룰 DB · 촬영 프로토콜 로드 |
| numpy | 마커 호모그래피 계산 |
| opencv-python | ArUco 마커 검출 · 영상 분석 · 마커 카드 생성 |
| Pillow | 문자 높이 계수 교정 |
| pytest | 테스트 (개발용) |

### 1-3. 한 번에 점검

```bash
python setup_check.py
```

파이썬 버전 → 패키지 → 룰 DB → 저작권 가드 → 테스트 → 마커 생성 → 데모까지
순서대로 돌려 보고 무엇이 되고 무엇이 안 되는지 알려준다.
**전부 `[ OK ]` 가 나오면 설치 끝이다.**

> 서버·데이터베이스·클라우드 계정 **아무것도 필요 없다.**
> 지금 단계는 전부 로컬에서 돈다.

## 2. 오늘 할 것 — 인쇄 두 장

### 2-1. 마커 카드

```bash
python tools/make_marker.py --sheet
```

`assets/BFK-MARK-A_A4_sheet.png` 을 인쇄한다.

**인쇄 설정이 전부다. 틀리면 모든 치수 판정이 틀어진다.**

- 배율 **‘실제 크기’ 100%** — `용지에 맞춤`, `축소하여 인쇄` **금지**
- 용지 **무광 코팅 200g 이상** — 유광은 화면 반사와 겹쳐 검출이 안 된다
- 인쇄 후 **카드의 20mm 눈금자에 실제 자를 대어 확인**한다.
  20mm 가 아니면 배율이 틀린 것이다. 다시 인쇄한다.

카드는 4장 나온다(id 0~3). 평면마다 다른 id 를 쓰면 나중에 어느 평면인지 구분된다.

### 2-2. 현장 촬영 체크리스트

```bash
python tools/make_field_sheet.py --html
```

`assets/field-sheet.html` 을 브라우저에서 열고 `Ctrl+P` 로 인쇄한다.

수집 앱이 없어도 이 종이 한 장이면 현장에 나갈 수 있다. 안에 다 들어 있다 —
촬영 전 확인, 24개 컷 목록, 마커 부착 위치, 점주 문항 4개, 실측 의뢰 7항목, 개인정보 처리.

> 내용은 손으로 쓴 게 아니라 `capture-protocol.yaml` 에서 자동 생성된다.
> 프로토콜을 고치면 체크리스트도 따라 바뀐다.

## 2-3. 수집 앱 — 폰에서 촬영

```bash
KFA.exe serve-app
```

화면에 뜨는 `http://192.168.x.x:8099/` 를 **폰 브라우저로 열면** 된다.
촬영물은 폰 안에만 있고, 사진마다 가리기(마스킹)를 거쳐 저장된다.

> **http 로 열면 오프라인이 안 된다. 이 PC 와 같은 와이파이 안에 있어야 한다.**
>
> 서비스 워커(앱을 폰에 저장하는 기능)는 브라우저가 **보안 연결로 인정하는 주소**
> — `https://` 또는 `localhost` — 에서만 등록된다. 폰이 쓰는 `http://192.168.x.x`
> 는 여기에 해당하지 않아 `navigator.serviceWorker` 가 아예 존재하지 않는다.
> 실제로 폰과 같은 조건에서 확인한 값이다:
>
> ```
> origin: http://192.168.0.17:8099
> isSecureContext: false
> 'serviceWorker' in navigator: false
> ```
>
> 찍은 사진은 IndexedDB 에 남으므로 **잃지는 않는다.** 다만 와이파이를 벗어나면
> 앱 화면이 다시 열리지 않는다. 앱도 접속하면 같은 내용을 주황색 띠로 알린다.

### 2-3-1. 오프라인으로 쓰기 — https (권장)

인증서를 만들고 폰에 **한 번** 설치하면 앱이 폰에 저장되어 와이파이를 벗어나도 촬영이 이어진다.

```bash
KFA.exe cert
```

`assets/cert/kfa-ca.crt` 를 폰으로 보내 설치한 뒤:

```bash
KFA.exe serve-app --https
```

- **Android** — 파일을 열면 설치 화면. 안 뜨면 설정 → 보안 → 암호화 및 자격증명 →
  인증서 설치 → CA 인증서
- **iPhone** — 파일을 열면 '프로파일 다운로드됨' → 설정 → 일반 → VPN 및 기기 관리 →
  프로파일 설치. 그다음 **반드시** 설정 → 일반 → 정보 → **인증서 신뢰 설정**에서
  `KFA Field Capture CA` 스위치를 켠다. 이걸 빠뜨리면 https 가 먹지 않는다.

> **자체 서명만으로는 안 된다.** 경고를 눌러 통과해도 브라우저가 보안 컨텍스트로
> 쳐 주지 않아 서비스 워커가 등록되지 않는다. CA 를 신뢰 목록에 넣어야 한다.
> 그래서 이 도구는 CA 와 서버 인증서를 따로 만들고, LAN IP 를 SAN 에 넣는다.
>
> CA 개인키는 진단 PC 에만 남고 어디에도 전송되지 않는다.
> 앱 화면 위에 주황색 띠가 **없으면** 오프라인 저장이 켜진 것이다.

앱이 하는 일

- 촬영 세트 24컷을 순서대로 안내하고, 빠진 컷을 막는다
- 마커가 안 보이면 **그 자리에서** 다시 찍으라고 알려준다 (예비 확인)
- 얼굴·카드번호를 문질러 가린다 — 원본은 저장하지 않는다
- 점주 문항 4개를 받는다
- 제출 전에 **지금 제출하면 몇 항목이 미판정으로 남는지** 먼저 보여준다
- ZIP 한 개로 내보낸다

## 3. 이번 주 할 것 — 현장 리허설 1곳

**폰(수집 앱) + 인쇄물 두 장**으로 한 곳을 찍어 본다.
목적은 데이터 수집이 아니라 **프로토콜이 현장에서 성립하는지 확인**하는 것이다.
앱 없이 종이 체크리스트만으로도 된다 — 둘 다 같은 24컷을 안내한다.

1. 마커를 화면 베젤에 붙이고 S1 을 찍는다 → **사진에서 마커가 선명하게 보이는가**
2. 조작 영상을 30fps 이상으로 찍는다 → **음성이 같이 녹음되는가**
3. 측면·하부를 찍는다 → **바닥면이 프레임에 들어오는가** (높이 기준선)
4. 점주 문항 4개를 실제로 물어본다 → **이어폰을 꽂아볼 수 있는가**
5. 사진 한 장을 골라 마커 검출을 확인한다:

```bash
python -c "import cv2,numpy as np,sys; sys.path.insert(0,'.'); from engine.calc import scale; img=cv2.imdecode(np.fromfile(r'사진경로.jpg',dtype=np.uint8),cv2.IMREAD_COLOR); r=scale.detect_marker_corners(img); print('검출' if r else '미검출'); s=scale.build_plane_scale(r[0],plane='display',frame_width_px=img.shape[1]); print(f'배율 {s.px_per_mm:.2f}px/mm 왜곡 {s.skew:.2f} 확신도 {s.confidence}')"
```

`배율`, `왜곡`, `확신도` 가 나오면 **마커 기반 치수 측정이 실제로 성립한다는 증명**이다.
이게 이 사업에서 가장 먼저 확인해야 할 것이다.

리허설에서 나온 문제는 `rules/capture-protocol.yaml` 을 고쳐 반영한다.
고친 뒤 `python tools/validate_rules.py` 로 룰 DB 와 어긋나지 않는지 확인한다.

## 4. 진단 — 앱이 찍어 온 것을 읽는다

앱이 내려준 ZIP 을 풀고:

```bash
KFA.exe ingest "C:\경로\GB-CAFE-001_20260822"
```

진단 PC 가 하는 일

1. `manifest.json` 을 읽어 기기·조건부 기능·점주 응답을 확인한다
2. 사진마다 **마커를 찾아 평면을 환산**한다 (실패하면 그 사진은 치수 계측에서 뺀다)
3. 문자 영역을 찾아 **명도 대비(3.i·3.j)** 를 계산한다
4. (OCR 엔진이 있으면) 문구를 읽어 **문자 높이(3.g)** 를 잰다
5. 마커 평면에서 **작동부 윤곽을 찾아 간격(1.b)·경계상자(1.c)** 를 잰다
6. 영상에서 **깜박임(8.a)** 주파수를 잰다
7. 점주 응답과 실측값을 그대로 기록한다
8. (`--l2` 를 붙였다면) 촬영물을 보고 판단하는 25항목을 선별한다
9. 자동 판정하지 못한 항목에 **다음 담당**을 붙인다
10. 리포트 4종을 저장한다 — `report.md` · `matrix.csv` · `todo.csv` · `result.json`

시험해보려면 데모 번들을 쓴다:

```bash
KFA.exe demo-bundle
KFA.exe ingest
```

**자동 판정되는 항목** — 3.i, 3.j, 1.b, 1.c, 8.a. 나머지는 담당자에게 넘어간다.
적다고 느껴진다면 정확한 인식이다. 그래서 리포트가 그 사실을 인쇄한다.

> **치수 계측은 마커가 있어야만 한다.** 마커가 안 잡힌 사진에서는 1.b·1.c 를
> 계산하지 않는다. 픽셀 값을 그럴듯한 mm 로 바꿔치기하는 순간 리포트 전체의
> 신뢰가 무너지기 때문이다.
>
> 그리고 작동부 윤곽 검출은 **화면의 모든 버튼을 빠짐없이 찾는다고 보장하지 않는다.**
> 그래서 위반을 찾으면 '위반 의심'으로 올리지만, 못 찾았다고 '적합'을 선언하지 않는다.
> 합성 촬영 검증에서 기울기 0.25 까지 치수 오차 0.3mm, 간격 오차 0.05mm 였다.

CSV·JSON 이 필요하면:

```python
from engine.report import to_csv, undetermined_csv, to_json
open("matrix.csv", "w", encoding="utf-8").write(to_csv(bundle))
open("todo.csv", "w", encoding="utf-8").write(undetermined_csv(bundle))
```

CSV 는 BOM 이 붙어 있어 한글·엑셀에서 인코딩이 깨지지 않는다.
`todo.csv` 는 그대로 실측 업체·점주에게 넘기는 작업 목록이다.

## 5. 개발이 남은 것 — 우선순위와 필요한 것

여기서부터는 **개발자가 붙어야 한다.** 순서대로 하는 게 맞다.

### 우선순위 1 — L2 판정 켜기 (설치만 하면 된다)

**코드는 이미 다 있다.** 별표5 25항목(judge 23 + screen 2)이 여기 달려 있다 —
색 단독 사용, 레이블 적절성, 용어 난이도, 한 손 조작 가능 여부 등.
지금은 공급자가 설정되지 않아 이 항목들이 검토자에게 넘어가고 있을 뿐이다.

`anthropic` SDK 는 **이미 설치돼 있다.** 환경변수 두 개만 잡으면 된다.

```bash
set ANTHROPIC_API_KEY=sk-ant-...
set KFA_L2_PROVIDER=anthropic
KFA.exe ingest "C:\진단\번들폴더" --l2
```

- **필요한 것**: **LLM API 키 1개**. 이게 이 프로젝트에서 유일하게 필요한 외부 계정이다
- **비용 감각**: 진단 1건에 화면 20장 + 판정 25항목 기준으로 **건당 수백 원~수천 원** 수준.
  실증 2곳이면 무시할 수 있는 금액이다
- **기본은 꺼짐이다.** `--l2` 를 붙이지 않으면 사진이 밖으로 나가지 않는다.
  붙이면 무엇이 전송되는지 화면에 찍히고 동의를 묻는다 (`--yes` 로 건너뛸 수 있다)

> **모델의 '적합'은 적합이 아니다.**
> 룰이 `both` 인 항목이라도 L2 를 거친 판정은 `fail_only` 로 눌린다.
> 모델은 위반 후보를 골라 주는 데까지고, 적합 선언은 사람이 한다.
> 그래서 L2 를 켜도 리포트의 '적합' 개수는 늘지 않는다 —
> **검토자가 봐야 할 것이 무엇인지가 좁혀질 뿐이다.** 그게 이 계층의 값어치다.

**주의**: 촬영물에 개인정보가 있으면 외부로 보내기 전에 마스킹해야 한다.
`capture-protocol.yaml` 의 `privacy.on_device_masking` 이 그 규칙이고,
수집 앱이 기기에서 처리한다. 그것으로 충분하다고 가정하지 말고 한 번 더 확인한다.

### 우선순위 2 — OCR (설치·교정 완료)

**끝났다.** 3.g(문자 높이)가 한글까지 자동 판정된다.
설치돼 있으면 자동으로 잡아 쓰므로 `--l2` 같은 스위치가 없다.
전부 로컬에서 돌고 사진이 밖으로 나가지 않는다.

```bash
pip install rapidocr        # 이미 설치됨
KFA.exe calibrate-ocr       # 이미 교정됨
```

| 엔진 | 한글 | 상태 |
|---|---|---|
| **rapidocr** (PP-OCRv5 korean) | **4 / 4** | **사용 중** · 계수 0.8252 · 산포 0.077 |
| rapidocr-onnxruntime (구 패키지) | 0 / 4 | 쓰지 말 것 — 중/영문 전용 |
| paddleocr | ○ | 파이썬 3.14 용 휠 없음 |
| tesseract | △ | 실행파일·`kor` 언어데이터 별도 설치 |

한글 화면으로 전 구간을 검증한 결과다. 정답을 아는 문자 높이를 합성 화면에
그려 넣고, 마커를 붙여 비스듬히 찍은 뒤 되찾아 본 값이다.

| 문구 | 참 잉크 높이 | 측정 | 오차 |
|---|---|---|---|
| 주문하기 | 15.88mm | 15.48mm | −2.5% |
| 결제 수단 선택 | 11.88mm | 11.84mm | −0.3% |
| 영수증 출력 | 6.62mm | 6.05mm | −8.7% |
| 취소 | 8.25mm | 7.42mm | −10.0% |

> **왜 교정이 필수인가.** 문자 높이 판정은 OCR 상자가 *무엇을 감싸느냐*에 통째로 달려 있다.
> 구 엔진의 계수는 **1.4764**(상자가 잉크보다 작다), 새 엔진은 **0.8252**(상자가 잉크보다 크다) —
> 방향이 정반대다. 그래서 교정 키에 **모델과 언어를 넣는다**(`rapidocr:PP-OCRv5:korean`).
> 이름만으로 키를 삼았다면 새 엔진이 구 계수를 물려받아 문자 높이를 79% 과대평가하고
> **실제 위반을 놓쳤을 것이다.** 모델을 바꾸면 교정이 없는 상태로 되돌아간다.

> **±10% 는 남는다.** 같은 화면을 다시 찍으면 그만큼 흔들린다.
> 과대평가 쪽이 위험하므로(6.6mm 글자가 7.3mm 로 읽히면 기준을 통과한다),
> 기준선 언저리는 **적합이라 말하지 않고 '경계 근접'으로 실측에 넘긴다.**
> 허용오차는 교정 산포에서 자동으로 가져온다 — 손으로 정한 값이 아니다.

> **이름을 믿지 않는다.** 엔진이 실제로 한글을 읽어 보고(`Provider.probe_korean`)
> 못 읽으면 교정 기록과 리포트에 그대로 적는다. 그래서 한글을 못 읽는 엔진을 붙이면
> 3.g 가 '위반 없음'이 아니라 **'읽지 못함'으로 실측에 넘어간다.**

인식 모델은 최초 1회 약 18MB 를 내려받아 패키지 폴더에 저장한다. 그 뒤로는 네트워크가 필요 없다.
지금 상태는 `KFA.exe gaps` 의 'OCR 계층' 줄이 알려준다 — 코드·연결·엔진·상자 계수 네 가지.

### 우선순위 3 — 수집 앱 호스팅 (선택)

지금은 `KFA.exe serve-app` 으로 진단 PC 가 앱을 내준다. 같은 와이파이가 전제다.
현장이 여러 곳으로 늘어나면 정적 호스팅(월 1만 원 미만)에 올리면 된다.
앱은 정적 파일뿐이라 그대로 복사하면 끝난다.

### 우선순위 4 — 검토자 콘솔 · API · DB

**실증 2곳 규모에서는 필요 없다.** 판정 레코드가 수십 건이면 파일로 충분하다.
다음 조건이 되면 그때 만든다.

- 진단 건수가 월 10건을 넘을 때
- 검토자가 2명 이상일 때
- 점주가 자기 리포트를 직접 열어봐야 할 때

## 6. 서버가 필요해지는 시점

**지금은 아니다.** 아래 중 하나가 생기면 그때 필요하다.

| 언제 | 무엇이 필요한가 | 대략 |
|---|---|---|
| 점주가 리포트를 링크로 열어야 할 때 | 정적 호스팅 | 월 1만 원 미만 |
| 수집 앱에서 업로드를 받아야 할 때 | 오브젝트 스토리지 + API 서버 | 월 3~5만 원 |
| 검토자가 여럿이서 큐를 나눠 쓸 때 | + 데이터베이스 | 월 5~10만 원 |
| 촬영물을 장기 보관해야 할 때 | + 스토리지 (사진·영상이 무겁다) | 용량 비례 |

> 1차년도 예산(3,600만 원) 기준으로 인프라 비용은 문제가 되지 않는다.
> 문제는 **인건비가 들어갈 개발 순서**이고, 그래서 5장의 우선순위가 중요하다.

## 자주 막히는 곳

**`pip` 가 없다고 나온다**
파이썬 설치 시 `Add python.exe to PATH` 를 안 켰을 가능성이 높다.
Windows 는 `py -m pip install -r requirements.txt` 로 우회된다.

**한글이 깨져 보인다**
Windows 터미널에서 실행 전에 한 번:
```bash
set PYTHONUTF8=1
```

**마커가 검출되지 않는다**
순서대로 확인한다 — ① 인쇄 배율 100% ② 무광 용지 ③ 마커가 프레임 폭의 3% 이상
④ 정면에 가깝게(왜곡비 2.5 이하) ⑤ 초점이 마커에 맞았는지.
`build_plane_scale` 이 이유를 문장으로 알려준다.

**`opencv-python` 설치가 오래 걸린다**
정상이다. 휠이 크다. 한 번만 받으면 된다.
